ВХОД ЧЕРЕЗ DISCORD — настройка

1. GitHub: замените сайт содержимым полного архива, включая docs, source, components-source, README, LICENSE и уведомления. Папка docs содержит готовую сборку. Сохраните прежний способ публикации Pages. Дождитесь публикации.

2. Wispbyte: остановите бота, сделайте резервную копию и замените папку bot-api файлами из обновления API (или полного архива бота). СОХРАНИТЕ текущие .env и data. Файл запуска остаётся bot-api/start-with-editor.cjs. При следующем запуске installer обновит общие маршруты в src, сохранив транскрипты и supervisor. Не запускайте server.cjs отдельно: он используется в общем HTTP-сервере бота.

3. Discord Developer Portal → приложение бота 1519310493750263838 → OAuth2 → Redirects. Добавьте ТОЧНО:
https://lolekx-api.wispbyte.app/api/oauth/callback
Сохраните настройки. Это адрес API, а не адрес GitHub Pages.

4. В том же приложении возьмите OAuth Client Secret и добавьте его на Wispbyte в DISCORD_CLIENT_SECRET. Это секрет приложения OAuth, а НЕ Discord Bot Token. Не присылайте его в чат и не добавляйте в GitHub/код сайта.

5. В .env на Wispbyte добавьте значения из bot-api/editor.env.example. CLIENT_ID и OWNER_USER_ID уже указаны по исходной конфигурации вашего бота; проверьте их, если меняли приложение или аккаунт владельца. EDITOR_AUTH_MODE=discord отключает прежний вход по паролю, даже если EDITOR_ACCESS_PASSWORD остался в .env.

6. Stop → Start. Откройте сайт с Ctrl+F5, нажмите «Войти через Discord», подтвердите аккаунт и разрешение identify. После возврата выберите сервер и канал.

Отправка разрешена OWNER_USER_ID (и только тем дополнительным ID, которые явно заданы в EDITOR_ALLOWED_USER_IDS). Обычный посетитель может редактировать локальный JSON, но не получает доступ к боту. email и список серверов пользователя не запрашиваются: серверы и каналы берутся у бота.

Черновик сохраняется на время перехода через Discord. Вход привязан к этому браузеру, возвращает одноразовый код, который можно обменять только с сохранённым подтверждением браузера. Сессия API живёт 4 часа и хранится только в памяти страницы; после обновления страницы потребуется снова войти. Logout/Disconnect отзывает сессию. Открывайте вход и возврат в одном браузере/вкладке. SessionStorage должен быть доступен. Вложения перед полным переходом нельзя сохранить автоматически: входите перед их загрузкой или используйте Webhook.

Если Discord пишет invalid redirect_uri: проверьте Redirects — адрес должен совпадать полностью, без / в конце. Если API возвращает ошибку настройки: проверьте .env и перезапуск. unauthorized означает, что вошёл аккаунт, которого нет в списке разрешённых ID. Ошибки OAuth не содержат секретов; пароль и токены не выводятся в консоль.

Проверены серверный OAuth и браузерный клиент с подменёнными ответами Discord, CORS, отказ чужому аккаунту, защита от повторов, вход/выход, сохранение черновика, передача одноразового кода и работа прежнего API. Реальный вход требует Client Secret и Redirects, настроенных на хостинге; реальные сообщения в Discord при проверке не отправлялись.
