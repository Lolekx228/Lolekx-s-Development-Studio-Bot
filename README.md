# LDS Studio · редактор на основе Discohook.app

Это адаптация открытого проекта **[Discohook.app](https://discohook.app/)** из [discohook/discohook](https://github.com/discohook/discohook), а не классического discohook.org. Оригинальные компоненты MessageEditor, EmbedEditor, редакторы Components V2, кнопок и меню, JSON, генератор кода и предпросмотр находятся в `source/upstream/app`. Версия исходного проекта закреплена в `source/UPSTREAM-COMMIT.txt`.

Рабочее название и изображения заменены на LDS Studio. Атрибуция и лицензия сохранены. Проект не связан с авторами Discohook или Discord. Распространяется по GNU AGPL v3 или более поздней версии; полный текст — LICENSE. Исходники публикуются вместе со сборкой в этом репозитории.

## Что работает

- Несколько сообщений в одном редакторе; сворачивание, перестановка, дублирование, удаление и переименование.
- Content, Thread, Profile, Files; embeds с Author, Body, Fields, Images и Footer.
- Кнопки, меню, текстовые блоки, контейнеры, секции, галереи и остальные поддерживаемые исходным редактором компоненты. Обычные embeds и Components V2 больше не открывают разные сайты или старую вёрстку.
- Опции сообщения: JSON, флаги, allowed mentions, генерация кода discord.js / discord.py; живой оригинальный предпросмотр.
- Прямое отправление webhook, выбор нескольких webhook и сообщений, вложения, тихая отправка, ветки и редактирование сообщения через Set Link.
- Отправление от LDS Bot через существующий HTTPS API, вход через Discord, выбор сервера/канала, вложения, создание форумной темы через Thread Name и редактирование собственных сообщений бота. Токен бота и OAuth Client Secret остаются на Wispbyte.
- Бекапы с несколькими сообщениями, импорт форматов 1–8 и d2, экспорт, открытие и перезапись открытого бекапа. В окне есть «Перенести старые бекапы» — чтение прежней базы LDS Studio на том же адресе в том же браузере. Старые данные эта кнопка не удаляет.
- Черновик и бекапы сохраняются локально после перезагрузки. История хранит последние 30 снимков при загрузке, очистке и отправке. Ссылки Share не содержат webhook или сессии. Файлы после перезагрузки/перехода по ссылке нужно выбрать заново.

## Бот на Wispbyte

Для входа используется прежний API `https://lolekx-api.wispbyte.app`. В архиве приложен совместимый `bot-api/`. Если расширенный API уже установлен, менять его для нового интерфейса не нужно. При обновлении старой версии загрузите только bot-api и сохраните действующий .env. Инструкция OAuth: НАСТРОЙКА-DISCORD.txt.

В режиме бота пинги пользователей/ролей задаются переключателем окна отправки. Для индивидуального Allowed Mentions используйте режим webhook: API бота пока принимает только общий переключатель pings. @everyone и @here в режиме бота выключены.

Кнопки с URL работают как ссылки. Для кнопок/меню с custom_id нужен соответствующий обработчик interactionCreate в вашем боте. Серверные сценарии Flow, облачные бекапы, создание webhook через сервис Discohook и его платные функции не подключены к этой статической адаптации. Обработчик компонента не регистрируется на чужом сервисе.

Сессия Discord сохраняется в sessionStorage текущей вкладки и проверяется API после перезагрузки. Её срок задаёт API (сейчас 4 часа); выход и перезапуск API прекращают сессию. Ошибка сети не удаляет сохранённую сессию. URL webhook находится только в памяти вкладки; после обновления страницы добавьте его снова.

## Сборка

Из папки source, Node.js 22/24:

```sh
npm ci --legacy-peer-deps
npm run build
node --test tests/core.test.mjs app/bot/client.test.cjs app/bot/oauth-browser.test.cjs app/bot/session.test.cjs
```

Сборка — Vite, React и Tailwind; результат записывается в ../docs. Для другого репозитория задайте LDS_BASE_PATH (например, /my-editor/). Сервер, Cloudflare и база PostgreSQL для самого редактора не нужны.

Изменения адаптации находятся в source/app, source/vite.config.ts и изменённых компонентах source/upstream/app. Там заменены главная страница, аккаунт и отправка; регистрация обработчиков компонентов сделана локальной; предпросмотр использует LDS Bot и свой логотип. Начальные публичные страницы, маршруты и серверные модули upstream оставлены как исходные материалы и не запускаются в статической сборке. Разработческие зависимости node_modules в архив не включены.

Проверено: статическая сборка, 19 тестов клиента/форматов/OAuth, 6 тестов API с имитацией Discord; в браузере — embed и предпросмотр, сохранение черновика после перезагрузки, сохранение/перезапись бекапа и Components V2. Реальные сообщения при проверке не отправлялись.
