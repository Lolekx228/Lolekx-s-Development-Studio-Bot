# LDS Studio: GitHub Pages + Wispbyte

Эта версия подготовлена для вашего варианта размещения: редактор — на GitHub Pages, бот и API отправки — на Wispbyte. Пока хостинг недоступен, редактор, шаблоны, предпросмотр, импорт и экспорт JSON работают без него. Реальное развёртывание на GitHub и Wispbyte ещё не выполнено.

## 1. Разместить сайт на GitHub

1. Создайте репозиторий, например lds-studio. Распакуйте архив и загрузите его файлы в корень репозитория (не сам ZIP), сохранив папки docs, bot-api и .github.
2. Откройте Settings → Pages → Source → GitHub Actions.
3. Workflow Publish LDS Studio автоматически опубликует только папку docs. Можно запустить его вручную через Actions → Publish LDS Studio → Run workflow.
4. Адрес проекта обычно имеет вид https://USERNAME.github.io/lds-studio/. Для подключённого аккаунта GitHub найден логин HerodrineYT; если используете этот аккаунт, origin будет https://herodrineyt.github.io.

Можно обойтись без Actions: в Settings → Pages выберите Deploy from a branch, ветку main и папку /docs. Тогда workflow-файл не нужен.

GitHub Pages размещает только статический сайт. Пароль редактора, токен Discord и .env бота не загружаются в репозиторий. Публичная страница позволяет редактировать сообщения любому посетителю, но отправка требует пароль API.

## 2. Подключить API к существующему боту на Wispbyte

У вашего бота уже есть HTTP-сервер транскриптов тикетов. API редактора использует тот же сервер в процессе бота и тот же порт 13579. Он добавляет маршруты /api/session, /api/discord/* и /healthz; текущие /health и /ticket-transcripts/* сохраняются. Отдельный сервер на занятом порту запускать не нужно.

1. Загрузите папку bot-api из архива рядом с корневым index.js существующего бота. Его package.json, src, data и assets остаются на хостинге. Дополнительные npm-пакеты для API не нужны; нужен Node.js 20+.
2. В .env существующего бота или его переменные окружения добавьте:

```env
EDITOR_ALLOWED_ORIGIN=https://herodrineyt.github.io
TICKET_TRANSCRIPT_PORT=13579
EDITOR_ACCESS_PASSWORD=ВАШ_ОТДЕЛЬНЫЙ_СЛУЧАЙНЫЙ_ПАРОЛЬ
```

Пароль — минимум 20 символов. EDITOR_ALLOWED_ORIGIN — origin сайта, без /lds-studio/. Если используете другой GitHub-аккаунт или домен, замените origin. DISCORD_TOKEN и GUILD_ID берутся из текущих настроек бота, копировать их в GitHub не нужно.

3. На Wispbyte задайте файл запуска bot-api/start-with-editor.cjs вместо index.js (команда эквивалентна node bot-api/start-with-editor.cjs). Этот файл установит маршруты и затем запустит исходный index.js бота с его обычным supervisor/restart-механизмом. Если панель запускает npm start, измените только scripts.start в текущем package.json бота на node bot-api/start-with-editor.cjs. Не заменяйте package.json бота файлом из репозитория сайта.
4. Перезапустите сервер. Установщик добавит маршруты в src/utils/ticketTranscriptServer.js и запуск общей HTTP-службы в src/index.js. Он сохраняет резервные копии *.lds-editor.bak, а повторные запуски не дублируют изменения. Если структура исходников отличается от показанной версии LDS Bot, установщик остановит интеграцию и покажет ошибку; исходный бот продолжит запуск.
5. /health должен как прежде отвечать ok. Новый /healthz должен отвечать {"ok":true}. API использует тот же 0.0.0.0:13579 и не запускает второго Discord-бота.
6. Для GitHub Pages нужен доступный HTTPS-адрес API. HTTP IP:порт не подходит для запросов из HTTPS-страницы. Настройте HTTPS-поддомен/прокси в своём плане Wispbyte либо собственный HTTPS reverse proxy к этому порту. Возможности конкретного сервера ещё не проверены. Если у вас только HTTP-адрес, сначала настройте HTTPS.

Официальная база знаний Wispbyte содержит разделы Host a Simple Website и Subdomains (Beta): https://wispbyte.com/kb .

## 3. Связать сайт и бот

Когда появится HTTPS-адрес API, впишите его в docs/config.js:

```js
window.LDS_CONFIG = {
  apiUrl: 'https://ВАШ-ПОДДОМЕН'
};
```

Изменение файла публикуется обычным коммитом в GitHub. Адрес API можно также ввести прямо на странице. Введите EDITOR_ACCESS_PASSWORD, нажмите Подключиться, выберите канал и отправьте сообщение.

Токен сессии хранится только в памяти вкладки. После обновления страницы, перезапуска API или истечения четырёх часов нужно войти заново. Кнопка Выйти завершает сессию. Пароль и токен Discord не записываются в localStorage; автосохранение самого сообщения работает как прежде.

Если API недоступен, продолжайте пользоваться редактором и кнопкой Копировать JSON для /say text. Обычные embeds и отправка вложенных файлов в этой версии не поддерживаются. Кнопки custom_id и меню требуют обработчиков в вашем боте.

## Структура и проверки

- docs/: готовый статический сайт для Pages, без сборки и зависимостей.
- bot-api/: HTTP API, вход по паролю, сессии, CORS и отправка через Discord REST.
- .github/workflows/pages.yml: публикация docs в Pages.
- tests/: проверки защищённого API и интерфейса.
- bot-api/install.cjs и start-with-editor.cjs: установка в общий сервер транскриптов и запуск исходного бота.

Выполните npm test в корне этого проекта. Тесты используют подменённые ответы Discord и не отправляют реальные сообщения. Проверяется вход, удаление сессии, CORS, выбор канала, ограничения JSON и отсутствие секретов в публичных файлах. Никакие файлы текущего бота или уже опубликованного сайта не изменены.

Официальная документация GitHub Pages: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages .
